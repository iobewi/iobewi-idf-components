# P0.1 Stack Reduction Guide (Procédure Correcte)

Objectif : Réduire stacks tasks fetch + audio pour économiser RAM.

---

## ⚠️ FORMULE CORRECTE (HWM = Free Min, PAS Usage)

`uxTaskGetStackHighWaterMark()` retourne **free min** (marge restante), **PAS** l'usage.

### Formule

Avec marge `m = 0.25` (25%) :

```
S_old        = stack allouée actuelle (bytes)
F_min        = HWM_min en bytes (= HWM_words * sizeof(StackType_t))
U_peak       = S_old - F_min  (usage au pic)

S_new_bytes  = U_peak / (1 - m)
             = (S_old - F_min) / 0.75

S_new_words  = S_new_bytes / sizeof(StackType_t)  (si API attend words)
```

Puis arrondir au KB supérieur (ou 256 words).

---

## Unités Critiques (ESP32-S3 / Xtensa)

### sizeof(StackType_t)

Sur Xtensa (ESP32-S3) : **StackType_t = uint32_t = 4 bytes**

Vérifier dans logs HWM initiaux : `[sizeof(StackType_t)=4]`

### xTaskCreatePinnedToCore()

Paramètre `usStackDepth` : **en WORDS** (pas bytes)

```c
// Exemple :
xTaskCreatePinnedToCore(task, "name", 14336, ..., ...);
// → 14336 WORDS = 14336 * 4 = 57344 bytes = 56 KB
```

**ATTENTION** : Certaines versions/wrappers peuvent attendre bytes. **Toujours vérifier logs HWM initial vs stack allouée.**

## Procédure P0.1 (Étape par Étape)

### 1. Baseline HWM (600s minimum)

Activer stack diag :
```bash
idf.py menuconfig
# → HLS Player Configuration → Stack diagnostics = Y
# → Component config → Log → Verbosity = Debug
```

Run 10 min :
```bash
idf.py build flash monitor | tee hwm_baseline.log
```

### 2. Extraire HWM_min

```bash
# Fetch task
grep "\[STACK\] HWM" hwm_baseline.log | grep hls_fetch | sort -k5 -n | head -5

# Audio task
grep "\[STACK\] HWM" hwm_baseline.log | grep audio_play | sort -k5 -n | head -5
```

Exemple output :
```
I (5000) hls_fetcher: [STACK] hls_fetch: HWM initial = 2500 words (10000 bytes) [sizeof(StackType_t)=4]
D (10000) hls_fetcher: [STACK] HWM=2400 words (9600 bytes free min) [hls_fetch]
D (15000) hls_fetcher: [STACK] HWM=2350 words (9400 bytes free min) [hls_fetch]  ← MIN
```

→ `F_min_fetch = 9400 bytes`

### 3. Calculer S_new

#### Exemple Fetch Task

Données :
- S_old = 14336 words * 4 = 57344 bytes  (si usStackDepth en words)
- F_min = 9400 bytes  (HWM min observé)

Calcul :
```
U_peak = 57344 - 9400 = 47944 bytes  (usage au pic)
S_new = 47944 / 0.75 = 63925 bytes
S_new_words = 63925 / 4 = 15981 words
Arrondi KB sup : 16384 words (64 KB)
```

**Résultat** : Aucune réduction possible (besoin plus de stack).
**Cause** : HWM trop faible → stack sous-dimensionnée actuellement.

#### Exemple Audio Task (HWM confortable)

Données :
- S_old = 6144 words * 4 = 24576 bytes
- F_min = 18000 bytes  (HWM min observé)

Calcul :
```
U_peak = 24576 - 18000 = 6576 bytes
S_new = 6576 / 0.75 = 8768 bytes
S_new_words = 8768 / 4 = 2192 words
Arrondi 256 words : 2304 words (9 KB)
```

**Résultat** : Réduction 6144 → 2304 words (**-3840 words = -15 KB**)

### 4. Appliquer Réduction

Modifier `components/iobewi_apps_hls_player/src/app_hls_player.c:186,192` :

```c
// AVANT :
BaseType_t ret = xTaskCreatePinnedToCore(hls_fetch_task, "hls_fetch", 14336, ...);
ret = xTaskCreatePinnedToCore(hls_audio_play_task, "audio_play", 6144, ...);

// APRÈS (exemple) :
BaseType_t ret = xTaskCreatePinnedToCore(hls_fetch_task, "hls_fetch", 14336, ...);  // Inchangé (HWM trop bas)
ret = xTaskCreatePinnedToCore(hls_audio_play_task, "audio_play", 2304, ...);  // -15 KB
```

### 5. Validation

Run 30-60 min + start/stop cycles :
```bash
idf.py build flash monitor | tee validation_reduced.log
```

Vérifier :
```bash
grep "\[STACK\] HWM" validation_reduced.log | grep audio_play | sort -k5 -n | head -5
```

**Critère succès** : `HWM_min >= 512 words` (2 KB marge minimum absolue).

Si HWM descend sous 512 words → augmenter stack par paliers de 256 words.

## Cas Réels Attendus (ESP32-S3 HLS Player)

### Fetch Task (TLS/HTTP/M3U8)

- Stack actuelle : 14336 words (56 KB)
- Usage typique : 40-50 KB (TLS handshake + HTTP buffers + callstack)
- **HWM attendu** : 1500-3000 words (6-12 KB free)
- **Réduction attendue** : Faible ou nulle (stack déjà optimisée)

### Audio Task (Décodage TS/AAC)

- Stack actuelle : 6144 words (24 KB)
- Usage typique : 8-12 KB (décodeur + buffers temporaires)
- **HWM attendu** : 3000-4000 words (12-16 KB free)
- **Réduction attendue** : -1 à -2 KB possible

**TOTAL GAIN RÉALISTE** : **-1 à -3 KB** (pas -8 KB comme estimé initialement)

---

## Erreurs Communes à Éviter

### ❌ FAUX : `S_new = F_min / 0.75`

Diviser HWM par 0.75 dimensionne sur la **marge**, pas sur l'usage.
→ Résultat : stack énorme, aucune économie.

### ❌ FAUX : Confondre words et bytes

Toujours vérifier `sizeof(StackType_t)` dans logs.
Sur Xtensa : 1 word = 4 bytes.

### ❌ FAUX : Baseline trop court (< 5 min)

TLS handshake + worst-case HTTP + M3U8 parsing peuvent arriver après 2-3 min.
→ Minimum 10 min, idéal 30-60 min.

### ❌ FAUX : Marge < 25%

FreeRTOS besoin marge pour événements rares (interruptions, asserts, debug).
→ Minimum 25%, recommandé 30-35% pour production.
