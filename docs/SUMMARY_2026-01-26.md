## 📊 Violations Identifiées

### Violation Majeure : `drv_vl53l0x`

**Type** : Taxonomie

**Description** :
```
drv_vl53l0x/include/drv_vl53l0x/
├── drv_vl53l0x.h        ✅
├── tof_config.h         ❌ → devrait être lib_vl53l0x_provider
├── tof_provider.h       ❌ → devrait être lib_vl53l0x_provider
├── tof_snapshot.h       ❌ → devrait être lib_vl53l0x_provider
└── vl53l0x_api/         ⚠️ (vendor code, toléré)
```

**Impact** :
- Driver pollué avec logique métier
- Difficile à maintenir
- Viole le principe de responsabilité unique

**Solution** :
- Extraire vers `lib_vl53l0x_provider/`
- Garder `drv_vl53l0x` comme driver pur

---

### Violations Mineures

#### `mw_scan_builder`

**Problème** :
- Manque `mw_scan_builder_types.h`
- Fonctions `scan_builder_*` au lieu de `mw_scan_builder_*`

**Solution** :
- Créer types header
- Renommer fonctions

---

#### `mw_uros_transport_usb`

**Problème** :
- Headers `esp_usbcdc_*` au lieu de `mw_uros_transport_usb_*`
- Manque structure canonique

**Solution** :
- Renommer headers
- Renommer fonctions

---

#### `app_scan_tof`

**Problème** :
- Header `scan_engine.h` au lieu de `app_scan_tof_types.h` + `app_scan_tof.h`
- Fonctions `scan_engine_*` au lieu de `app_scan_tof_*`

**Solution** :
- Créer structure canonique
- Renommer tout
